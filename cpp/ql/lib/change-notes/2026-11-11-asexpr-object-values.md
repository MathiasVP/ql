---
category: breaking
---
* `Node.asExpr` and `Node.asIndirectExpr` now consistently treat an expression that denotes an object (for example, a variable, a field, an array, or a string literal) as the object itself rather than its address. For example, if `buf` is an array then `n.asExpr() = buf` holds for the node that represents the contents of `buf`. Dereferencing an array or a string literal first converts it to a pointer to its first element, so `n.asIndirectExpr() = arg` still refers to the data that an argument `arg` points to when `arg` is a pointer, an array, or a string literal. However, `asIndirectExpr` no longer has a result for an object qualifier (such as `x` in `x.f()`) or for an object passed to a reference parameter. Use `asExpr` instead in those cases.
* For an expression `r` of reference type, `Node.asExpr` consistently represents the reference itself, not also the referred-to value. Dereferencing the reference counts as one indirection: if `r` has type `T*&`, `asIndirectExpr(1)` represents the pointer and `asIndirectExpr(2)` represents the `T` object. To track the value after conversions, use `asConvertedExpr` with `r.getFullyConverted()`, or `asIndirectConvertedExpr` for its indirections. This differs from `asParameter`, which represents the referred-to object for a parameter of reference type.
* `Node.asVariable` of a global or static variable of array type now represents the contents of the array instead of its address, just like `Node.asExpr` of the array. So `asIndirectVariable(1)` no longer has a result for such a variable. Use `asVariable` instead.
